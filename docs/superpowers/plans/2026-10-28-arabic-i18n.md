# Arabic i18n Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** Ship the whole velloxstudio.com site in Arabic at `/ar/…` with a correct RTL layout, a language switch, Arabic SEO metadata, and Arabic fields in the Sveltia CMS, leaving the English site byte-for-byte equivalent in content and URLs.

**Architecture:** Two root layouts via route groups, `src/app/(en)/` (English, `lang="en"`) and `src/app/(ar)/ar/` (Arabic, `lang="ar" dir="rtl"`). Every route file becomes a thin wrapper around a locale-aware page component in `src/components/pages/`. All copy lives in typed content modules; Arabic twins under `src/content/ar/` must match the English shape or `typecheck` fails. Projects become `<slug>.<locale>.json` with English fallback.

**Tech Stack:** Next.js 16 App Router (`output: "export"`), React 19, Tailwind CSS 4 (logical utilities, `rtl:` variant), `next/font/google` (IBM Plex Sans Arabic), Bun (`bun test` for unit tests), Sveltia CMS i18n (`multiple_files`).

**Spec:** `docs/superpowers/specs/2026-10-28-arabic-i18n-design.md`

## Global Constraints

- English URLs do not change; every Arabic URL is `/ar` + the English path (`/` → `/ar`).
- Modern Standard Arabic, formal business register, glossary in the spec is binding; brand and product names (Vellox Studio, ERPNext, Frappe, Shopify, Next.js) stay Latin; digits are Western (0–9).
- Fonts self-hosted through `next/font` only (CSP `font-src 'self'`). Arabic pages load IBM Plex Sans Arabic 300/400/500 and Geist Mono only; Optika and Geist are not loaded there.
- `[dir="rtl"]`: letter-spacing 0 on display and label text, display `line-height` ≥ 1.25, no `uppercase`.
- No physical direction utilities left in `src/` (`ml-`, `mr-`, `pl-`, `pr-`, `left-`, `right-`, `text-left`, `text-right`, `rounded-l`, `rounded-r`, `border-l`, `border-r`, `origin-left`, `origin-right`) except where a step names one on purpose.
- `ARABIC_LIVE` (in `src/lib/i18n.ts`, default `true`) gates together: the language switch, `hreflang` alternates, `/ar` sitemap entries, the Arabic `noindex`, and the verify script's reciprocity check.
- Accessibility baseline unchanged: reduced motion, keyboard menu, sr-only labels, AA contrast.
- Commits: `git -c user.name="bhamalawi-alt" -c user.email="bhamalawi@gmail.com" commit`, never stage `.claude/`, end messages with `Co-Authored-By: Claude Fable 5.1 <noreply@anthropic.com>`. Bun only (`bun run typecheck|lint|build|verify`, `bun test`).

## Review Focus

1. A visitor on `/ar/portfolio/atlas-fintech` clicking "English" must land on `/portfolio/atlas-fintech`, and the reverse; the switch must never drop the path or double the prefix (`/ar/ar/…`). Pinned in Task 1's `i18n.test.ts` (`alternatePath`, `stripLocale`).
2. A project whose `.ar.json` is missing or has an empty Arabic `summary` must render English text plus the "English only" note, never a blank card. Pinned in Task 9's `projects.test.ts`.
3. Arabic hero headlines at 375 px must not clip ascenders or overflow `max-w-[20ch]`; pinned by the visual checklist in Task 13 (screenshots at 375×812 of `/ar`, `/ar/services/brand-identity`, `/ar/contact`).
4. The contact form on `/ar/contact` must submit the same JSON keys as English plus `_language: "ar"`, and the email field must stay left-to-right; pinned in Task 7 (DOM check via `read_page` in the browser: `input[name=email][dir=ltr]`, hidden `input[name=_language][value=ar]`).
5. With `ARABIC_LIVE = false` no English page may emit `hreflang`, the sitemap must contain no `/ar/` URL, and `/ar` pages must carry `noindex`; pinned in Task 11 by running the verify script once with the flag flipped.
